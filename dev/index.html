QuicoptClient — Module

QuicoptClient — the Julia client for the Quicopt API.

Authors a model in JuMP and converts it (import_model) to the Quicopt v1 wire Program — the published, language-neutral schema — serializes it to bytes (encode), and solves it over HTTP (solve). The wire schema is generated from program.proto via ProtoBuf.jl (src/proto/, regenerated by gen/gen.jl), so the client's dependencies are all public (JuMP, ProtoBuf, HTTP, JSON3). See the README.

source

Installation

using Pkg
Pkg.add("QuicoptClient")

All dependencies are public — JuMP, ProtoBuf, HTTP, JSON3. No solver and no service internals ship with the client.

Quickstart

using QuicoptClient, JuMP

m = Model()
@variable(m, 0 <= x <= 4)
@variable(m, 0 <= y <= 4)
@objective(m, Max, 3x + 2y)
@constraint(m, x + y <= 5)

result = solve(m)                      # POSTs to the service; prints the result banner
@show result.status result.objective result.solution

The first call mints a free API key (cached at ~/.cache/quicopt/free_key) and replays it on later calls. Target a specific server with solve(m; base_url = "…"), and use async = true for the first call against a freshly-booted server (its worker warmup can time out a synchronous call).

The wire schema

The wire Program is the published API contract (proto/quicopt/modeler/v1/program.proto). The client's codec is generated from that .proto via ProtoBuf.jl (under src/proto/, regenerated by gen/gen.jl) — the client implements the contract without forking it. Because proto3 omits zero-valued scalars and does not canonicalize map order, the emitted bytes are decode-equivalent to the service's reference codec, not byte-identical; a separate verification harness proves that equivalence.

API reference

  • Modeling — import_model, encode: JuMP model → wire Program → bytes.
  • Transport — solve, QuicoptError: ship the bytes to the service.
